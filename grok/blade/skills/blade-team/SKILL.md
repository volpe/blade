# Blade team

**Load runtime:** from this skill's directory, read `../../runtime.md` if present. Verify the actual delegation, messaging, waiting, and workspace capabilities; do not assume all hosts support peer messages.

Read `../blade/SKILL.md` for Shared spine, then `../../team/workflow.md` and `../../team/expert-selection.md`. The team contract replaces lightweight defaults for staffing, checkpoints, delivery records, and polish. Role cards are optional templates, not a fixed team; use `../../team/roles/expert.md` for a purpose-built role and read existing cards only when useful.

1. Load the project's existing instructions and any linked team profile. Use `../../team/project-profile.md` only for missing context and the compact record shape; do not duplicate known project facts.
2. Reconcile the request, workspace and source state, existing delivery record, and prior approvals. Default to **Deliver + guided** unless the user has already chosen otherwise. Explore/Deliver controls scope; approval authority separately controls stage continuation.
3. Identify the outcome, domain, difficult decisions, risks, and evidence needed. Show a proportionate team and why each expert is needed. Give every expert a task-specific charter: purpose, viewpoint, key questions, expected evidence, and decision boundaries. Cover outcome acceptance, production, verification, and independent review without requiring fixed titles.
4. Report the real staffing/messaging mode once. Schedule selected experts within capacity, preserving independent review. Give each worker the workflow, relevant template, charter, bounded brief, actual peer IDs, and ownership. Keep the main session as coordinator, one writer per shared workspace, and one compact delivery record.
5. Run the applicable stages using real exchanges. Reassess expertise at milestones or when evidence reveals new needs; record additions, combinations, and retirements. At applicable scope, design, delivery, and release checkpoints, present concrete results and seek only approval not already granted. Offer autonomous continuation through a named boundary with explicit external-action scope.
6. Review actual team effectiveness at milestones; assign Team Steward when a separate process review is useful. Propose exact reusable instruction changes for user approval. Selecting experts and writing charters for this run is ordinary staffing, not permission to edit the installed skill or role library. Do not silently install monitors or claim a trial before one has run.

End with the current result, evidence/limitations, and one next action. A host that cannot start independent agents cannot deliver a claimed multi-agent run; disclose that gap and do useful preparation without invented role messages or sign-offs.
